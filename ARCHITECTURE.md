# Architecture overview

High-level map of the Jet Lag Hide+Seek companion codebase. Behavior-preserving by default; structural work lands in dependency-ordered waves (R1–R8).

## Layer diagram

```text
┌─────────────────────────────────────────────────────────────┐
│  routes/          Page shells, role map chromes, thin wire  │
├─────────────────────────────────────────────────────────────┤
│  components/      Presentation (map, tools, HUD, admin UI)  │
├─────────────────────────────────────────────────────────────┤
│  hooks/           React orchestration (session, tools, sync)│
├─────────────────────────────────────────────────────────────┤
│  state/           Client stores (session, activity log, …)  │
├─────────────────────────────────────────────────────────────┤
│  services/        IO — Firestore, HTTP, geo, session, edge  │
├─────────────────────────────────────────────────────────────┤
│  domain/          Pure rules — game, session, geometry, …   │
└─────────────────────────────────────────────────────────────┘
         │                              │
         ▼                              ▼
   functions/ (callables,         worker/ (asset cache,
   triggers, proxies)             PostHog proxy, CSP, SPA)
         │
         ▼
   crates/jetlag-geometry-kernel  (Rust → WASM geometry)
```

| Layer | Responsibility | May import |
|-------|----------------|------------|
| `domain/` | Pure game / geo / session rules | Other domain, stdlib, existing turf usage |
| `services/` | IO: Firebase, HTTP, caches | `domain/`, platform |
| `hooks/` | React orchestration | `domain/`, `services/`, `state/` |
| `components/` | Presentation | hooks sparingly, domain types |
| `routes/` | Page shells, thin wiring | hooks, components |
| `functions/` | Callable / trigger HTTP boundaries | `lib/`, co-located modules |
| `worker/` | Edge assets, proxies, CSP | No React / Firebase client SDK |
| `crates/` | WASM geometry kernel | Rust std only |

## Edge surfaces

### Cloudflare Worker (`worker/`)

Request routing order (see `worker/index.ts`):

1. PostHog reverse proxy  
2. Sentry tunnel  
3. CSP nonce / reporting  
4. Asset cache  
5. SPA fallback  

Keep `index.ts` a thin orchestrator; concerns live in dedicated modules.

### Firebase Functions (`functions/`)

- Public HTTP / callable names are exported from `functions/index.mjs` — **preserve export names** across refactors unless a PR lists a migration.
- Handlers live under `functions/handlers/` (re-export barrels) with implementations in domain folders (`session/`, `proxies/`, `triggers/`, `incident/`, …).
- Node 24 ESM; co-located `functions/test/` for handler unit tests.

## WASM geometry boundary

- Rust crate: `crates/jetlag-geometry-kernel/` (built via `wasm:build` / production Deploy).
- TS dispatch and ready bits: `src/domain/geometry/kernel/` (`KERNEL_WASM_READY`, `dispatchKernel*`).
- ESLint restricts imports into the kernel purity boundary — do not bypass with deep relative imports from UI layers.
- Do **not** duplicate kernel algorithm docs here; treat the crate + `src/domain/geometry/kernel/` as source of truth.
- Structural moves under `crates/` or `src/domain/geometry/` wait on the ship-board geometry gate (wave-1 cutovers merged; no active Wave-2 structural branch).

## Wave ownership (R1–R8)

| Wave | Focus | Primary touch set |
|------|-------|-------------------|
| R1 | Reliability foundations | `functions/session/`, session lifecycle handlers, `src/services/session/` offline queue |
| R2 | Edge boundaries | `worker/` docs + split, `functions/handlers/triggers.mjs` / proxies → domain folders |
| R3 | Map screen unification | `src/routes/map-screen/` shared core + role adapters / chrome slots |
| R4 | Tool hook framework | `src/hooks/tools/` — `useToolSession` + thin tool adapters |
| R5 | Firestore boundary | `src/services/firestore/` serialization split by document type |
| R6 | Geo services decomposition | `src/services/geo/` packages (overpass / elevation / geocoding / matching) |
| R7 | Native / plugin hygiene | `plugins/jetlag-live-activity/`, Capacitor shell touch only as needed |
| R8 | DevEx | `@/` path alias (`tsconfig` + Vite), import codemod, keep this doc current |

Each wave PR must include `## Player-visible / contract changes` (`None` or an explicit list). Default is zero player-visible change.

**File-size exception:** `src/domain/device/changelog.ts` is generated by release sync — do not hand-edit; exclude from LOC budgets.

## Testing ladder

Use the tightest check that covers the change (agents: targeted Vitest only — no bare full-suite `npm test` unless test infra changed).

1. **Targeted Vitest** — unit / component tests for touched modules (`npx vitest run <paths>`).  
2. **Typecheck / lint** — `npm run typecheck`; ESLint on touched paths.  
3. **Functions / worker** — `cd functions && npm test`; `npx vitest run worker/…` when edge code changes.  
4. **Emulator** — Firestore rules / serialization suites via `vitest.emulator.config.ts` when rules or serdes change.  
5. **E2E** — Playwright smoke / feature specs for map, tools, and session flows affected by the wave.  
6. **Build** — `npm run build` (includes WASM) before native/plugin or packaging-sensitive merges.

CI still runs the full pyramid on PRs; local agents stay on the targeted ladder above.
